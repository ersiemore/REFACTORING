# TDD и покрытие кода — регистрация на курсы EKEB

Практическая работа по теме **Test-Driven Development (TDD) и покрытие кода**.

В проекте реализован небольшой сервис регистрации студентов на дополнительные курсы колледжа EKEB с использованием цикла **Red → Green → Refactor** и тестов `unittest`.

## Цель работы

Отработать:

- разработку от требования к тесту;
- цикл Red-Green-Refactor;
- граничные и ошибочные сценарии;
- наследование классов;
- измерение покрытия строк и ветвей с помощью `coverage.py`.

## Реализованные требования

### Course

Класс `Course` принимает название курса и количество мест.

- `name` не может быть пустым;
- `capacity` должен быть положительным целым числом;
- `enrolled` при создании равен `0`;
- `available_places()` возвращает `capacity - enrolled`;
- `enroll()` регистрирует одного студента и возвращает количество оставшихся мест;
- при отсутствии свободных мест `enroll()` вызывает `ValueError`;
- `cancel_enrollment()` уменьшает количество зарегистрированных студентов на `1`;
- отмена при `enrolled == 0` вызывает `ValueError`;
- `is_full` возвращает `True`, когда курс заполнен, иначе `False`.

### IntensiveCourse

`IntensiveCourse` наследуется от `Course` и дополнительно хранит `hours_per_week`.

- допустимый диапазон: от `6` до `20` часов включительно;
- `6–10` часов → `средняя` нагрузка;
- `11–20` часов → `высокая` нагрузка;
- наследует `enroll()`, `available_places()` и `is_full`.

## Что проверяют тесты

Тестовый набор включает обычные, граничные и ошибочные сценарии:

- создание курса и начальное состояние;
- пустое название и неправильную вместимость;
- свободные места;
- одну и несколько регистраций;
- регистрацию на последнее место;
- попытку регистрации сверх `capacity`;
- отмену регистрации;
- повторную отмену при пустом списке регистраций;
- пустой, частично заполненный и полный курс;
- наследование `IntensiveCourse`;
- границы `6`, `10`, `11`, `20` часов;
- ошибочные значения `5` и `21`;
- работу унаследованных методов.

## Запуск

Проверить все тесты:

```bash
python -m unittest discover -v
```

Запустить конкретный файл тестов:

```bash
python -m unittest -v test_course_service.py
```

## Измерение покрытия

Установить `coverage.py`:

```bash
python -m pip install coverage
```

Запустить покрытие строк и ветвей:

```bash
coverage run --branch -m unittest discover
coverage report -m
coverage html
```

После этого:

- `coverage report -m` показывает текстовый отчёт;
- `htmlcov/` содержит подробный HTML-отчёт;
- в отчёте можно увидеть непокрытые строки и частично пройденные ветви.

## TDD

Работа выполнялась по схеме:

**Red** — сначала добавляется тест для нового поведения и проверяется его падение.

**Green** — добавляется минимальная реализация, необходимая для прохождения теста.

**Refactor** — структура и имена улучшаются без изменения наблюдаемого поведения, после чего снова запускается весь набор тестов.

Основные этапы соответствуют заданию: `Course` → `available_places` → `enroll` → `cancel_enrollment` → `is_full` → `IntensiveCourse` → измерение покрытия.
